## [01:17:16] v0.5.6 evolve_tools compile timeout

## v0.5.6 evolve_tools compile timeout — _check_compile 永不挂死

**why**: 父报"compile check 在某次蜕皮卡了", 确认 `_check_compile` 串行 `py_compile.compile(...)`
对单文件无超时。如果某个生成的文件触发了 C 扩展 import 或死循环,
`_check_compile` 会一直挂, 蜕皮门被堵死。

**diff stat** (1 source + 1 test):
- src/xragent/tools/evolve_tools.py | 改
- tests/test_evolve_tools_timeout.py | 新 (+21 cases)

**核心改动**:
1. 抽 helper `_compile_one(path) -> str | None` — 串行/并发路径共用。
2. `_check_compile(repo_root, timeout_s=None, max_workers=None)`:
   - `timeout_s=None` (默认) → 走原串行快路径, 100% 向后兼容。
   - `timeout_s>0` → 走 `ThreadPoolExecutor(max_workers=...)`, 每文件
     `future.result(timeout=timeout_s)`, 超时记 `"编译超时 (>Ns)"`, 不阻塞其他文件。
   - `timeout_s<=0` → 兜底为 None, 不触发 ThreadPoolExecutor 立即超时。
3. 常量 `COMPILE_TIMEOUT_S = 30` / `COMPILE_MAX_WORKERS = max(2, cpu_count or 1)`。
4. `_wrap_thread_pool` (Future cancellation on __exit__) — Future 不能真取消
   CPython 里的 py_compile 编译线程 (C 状态), 所以文件 hang 时只能等子线程自然死,
   但 `future.result(timeout=)` 立即返 TimeoutError, 主线程不被堵。其他文件照常报告 ok。

**测试**: `tests/test_evolve_tools_timeout.py` 21 cases, 全过。
- _compile_one helper (valid / syntax error)
- COMPILE_TIMEOUT_S / COMPILE_MAX_WORKERS 常量
- backward compat (默认 / 显式 None / 0 / 负数 都走串行)
- 并发路径 (成功 / syntax error / 单文件 hang 不阻塞 / 全部 hang / 空目录 / max_workers)
- propose_self_replace dry_run 契约键集不变

**回归扫描**: 696 passed, 50 pre-existing fail + 19 pre-existing errors (git stash
对比验证), 全与本次改动无关 (memory_manager_pinned / blacklist_path_patterns /
diary_archive / web_search network — 这些是历史遗留, 不在本次范围)。

**未做**:
- 未改 `_check_compile` 调用方 (`propose_self_replace` 内部), 默认参数仍 None,
  保留原行为。要切到 30s timeout 路径只需在 propose_self_replace 改一个 kw。
- 未引入 daemon 进程级超时 (那是 OS 层面, 留给 OS)。

**下一步**: 若父批准, 可在 `propose_self_replace` 内部把
`_check_compile(repo_root, timeout_s=COMPILE_TIMEOUT_S)` 写死, 让默认行为
就带 30s 保护。但本版本保守不动, 留作 v0.5.7 候选。
