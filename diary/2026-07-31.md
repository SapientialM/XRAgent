## [02:38:59] tools(read_file): 加 original_size 字段, 让 LLM 单次 read 即知文件总字节数

### 动机
LLM 用 read_file 时只能看到 size (返回的字符数) 和 truncated (bool), 不知道文件原始大小。如果 truncated=False, LLM 无法区分 "文件 100B 全文返回" vs "文件 100MB 但没传 max_bytes 也走全文"; 如果 truncated=True, 还得再走一次 list_dir 才能知道文件多大盘。每次估算 context 都得多花一个 round trip。

### 改动
- `src/xragent/tools/fs_tools.py::read_file`: 成功后多 stat 一次拿 `st_size`, 返回 dict 加 `original_size` 字段 (字节, 恒报, 不论截断与否)
- `size` 保留不变 (返回字符数), `original_size` 是新增 (字节); UTF-8 多字节下两者故意不一致, 注释明确区分
- `_read_text_capped` 签名 2-tuple 不动 (白盒测试锁的就是 2-tuple), 多花一次 stat (μs 级) 换契约稳定
- `src/xragent/tools/registry.py`: 工具描述补一句 "返回字段含 original_size 与 size"

### 测试
- `tests/test_fs_tools.py`: 三处现有 case 加 original_size 断言 (happy / default / truncate)
- 新增两条锁契约:
  - `test_read_file_reports_original_size_for_non_truncated_utf8` — "中文abc" (9B / 5char) 验证 size != original_size
  - `test_read_file_original_size_reflects_actual_disk_size` — 5000B 文件 max_bytes=50, 锁 original_size=5000 而非被截断后的 50

### 结果
`pytest tests/test_fs_tools.py` 25/25 通过。diff stat: +66/-6 (3 files)。
- src/xragent/tools/fs_tools.py | +16/-6
- src/xragent/tools/registry.py | +1/-1

### 备注
