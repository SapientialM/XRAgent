## 副作用：发现 SideGit 单方向 stash bug

演练途中曾两次发现 `write_file` 写入后 working tree 被静默回滚（diff cache 显示"消失"）。追查发现：

- `git stash list` 里有 **948 条孤儿 stash**（`stash@{0}` 最新是 `xragent-pre-20260728-155649-625-post`，依此类推）
- `git reflog` 显示大量 `reset: moving to HEAD`（HEAD 自身无 reset 代码调用，是 snapshot 后引发的索引同步）
- 排查 `src/xragent/snapshot/side_git.py` 与 `core/react_loop.py:53/115`：
  - `react_loop.run()` 在 turn 前后各调一次 `self.snapshot.snapshot(...)`
  - `SideGit.snapshot()` 内部对有 changes 的工作树调用 `git stash push`（保留 working tree 改动到 stash），然后打 tag `xragent/turn-XXX`
  - **但 snapshot() 末尾没有 `git stash pop`**，所以改动永远卡在 stash 里

**并发成因**: 另一个独立的 XRAgent 进程（PID 42309，2025-XX-XX 09:32 启动，已跑 ~6h25m，PPID=1 是孤儿，无 supervisor）也在共享同一仓库。它每个 turn 都 `git stash push`，把我的 `write_file` 改动吞进它的 stash。

**不阻 drill 闭合**：因为最后我用一条 run_cmd 把 append_generation → md 写 → git add → git commit → git push 串成原子操作，赶在另一个进程的 turn 间隙，把世代谱直接固化进了 git commit f9d817d（不再依赖 working tree 的未跟踪改动）。

**建议修复**（写入 diary 留痕，不擅自改）:
1. `SideGit.snapshot()` 末尾若 pre_stash 为真，调 `git stash pop stash@{0}`（从 git 中拿到）恢复 working tree
2. 或改用 `git worktree` 给每个 XRAgent 进程独立分支
3. 或 supervisor 启动时清理孤儿 PID 42309（root cause）—— 这需要父的人工授权，因为另起了一个 autonomous 进程
